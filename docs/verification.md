# 이관 검증 노트

`migration`은 Oracle 데이터를 PostgreSQL로 옮기는 과정을 Spring Batch로
구성해 본 프로젝트입니다.

이관 작업을 정리하면서 가장 크게 느낀 점은, 구조를 멋지게 만드는 것보다
“정말 빠짐없이 옮겨졌는가”를 확인하는 일이 더 중요하다는 것입니다.
그래서 이 문서에는 제가 이관 코드를 보강하면서 확인한 부분과, 다음에 더
검증하고 싶은 부분을 정리했습니다.

## 현재 코드에서 확인한 부분

- `MigrationSqlBuilderTest`로 동적 INSERT SQL이 의도한 형태로 만들어지는지 확인했습니다.
- schema, table, column 이름이 안전한 형식인지 SQL 생성 전에 검사하도록 분리했습니다.
- 위험한 테이블명이나 빈 컬럼 목록이 들어오면 SQL을 만들지 않고 예외를 발생시킵니다.

## 앞으로 더 보강하고 싶은 부분

| 확인할 부분 | 이유 |
| --- | --- |
| 원본/대상 테이블별 건수 비교 | 누락되거나 중복 적재된 데이터가 없는지 확인하기 위해 |
| 실패 후 재실행 | 중간에 실패했을 때 처음부터 다시 밀어 넣지 않기 위해 |
| 제외 테이블 관리 | 시스템 테이블이나 임시 테이블이 섞이지 않도록 하기 위해 |
| 참조 관계 순서 | FK 관계 때문에 적재 순서가 꼬이지 않도록 하기 위해 |
| 테이블별 처리 시간 | 병목이 특정 테이블인지, 커넥션 풀 설정 문제인지 보기 위해 |

## 로컬 확인 명령

```bash
./gradlew test
```

아직은 SQL 생성 안전성을 중심으로 테스트를 추가한 단계입니다. 다음 단계에서는
H2나 Testcontainers를 붙여서 “읽기 → 쓰기 → 건수 비교”까지 이어지는 통합
테스트를 추가하고 싶습니다.
